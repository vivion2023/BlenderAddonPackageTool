# 统一通信协议设计文档

## 1. 设计目标

### 1.1 背景

当前系统中，Blender 发送指令给视觉引导系统，如果是操纵真实机器人的指令，就直接调用真实机器人的 SDK 进行运作。这种设计存在以下问题：

- **耦合度高**：指令处理逻辑与 SDK 调用紧密耦合
- **扩展性差**：新增执行目标需要修改多处代码
- **协议不统一**：不同来源的消息格式不一致

### 1.2 目标

设计一套统一的通信协议，实现：

1. **统一消息格式**：所有消息采用统一的结构
2. **统一指令抽象**：定义通用的机器人指令格式
3. **指令转换解耦**：指令解析/转换模块与 SDK 执行模块分离
4. **双向通信支持**：支持图像数据上传和运动指令下发

### 1.3 通信方向

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            视觉引导系统（服务端）                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐   │
│  │  目标检测    │  │  位姿转换    │  │  指令生成    │  │  指令转换    │   │
│  │    模块      │  │    模块      │  │    模块      │  │    适配器    │   │
│  └──────────────┘  └──────────────┘  └──────────────┘  └──────────────┘   │
│         ↑                                                    ↓              │
│         │              ┌──────────────┐                      │              │
```

## 3. 统一消息协议

### 3.1 基础消息格式

所有 WebSocket 消息采用统一的 JSON 格式：

```json
{
  "message_id": "uuid-string",
  "type": "消息类型",
  "sender": {
    "client_id": "客户端标识",
    "client_type": "客户端类型"
  },
  "target": {
    "client_id": "目标客户端标识（可选）",
    "client_type": "目标客户端类型（可选）"
  },
  "timestamp": 1234567890123,
  "payload": {
    // 具体消息内容
  },
  "metadata": {
    "request_id": "关联请求ID（可选）",
    "priority": 0,
    "ttl": 30000
  }
}
```

### 3.2 字段说明

| 字段       | 类型   | 必填 | 说明                                   |
| ---------- | ------ | ---- | -------------------------------------- |
| message_id | string | 是   | 消息唯一标识（UUID）                   |
| type       | string | 是   | 消息类型                               |
| sender     | object | 是   | 发送者信息                             |
| target     | object | 否   | 目标接收者，空表示由服务端路由         |
| timestamp  | number | 是   | 消息时间戳（毫秒）                     |
| payload    | object | 是   | 消息负载，具体内容由 type 决定         |
| metadata   | object | 否   | 元数据，包含请求关联、优先级等附加信息 |

### 3.3 客户端类型

| 类型    | 说明               |
| ------- | ------------------ |
| web     | Web 前端应用       |
| blender | Blender 虚拟环境   |
| robot   | 真实机器人控制器   |
| camera  | 独立相机设备       |
| server  | 视觉引导系统服务端 |

## 4. 消息类型定义

### 4.1 消息类型分类

```
消息类型
├── 系统消息 (system)
│   ├── register          - 客户端注册
│   ├── register_ack      - 注册确认
│   ├── heartbeat         - 心跳
│   ├── heartbeat_ack     - 心跳响应
│   └── error             - 错误消息
│
├── 图像消息 (image)
│   ├── image_frame       - 单帧图像
│   ├── video_stream      - 视频流数据
│   └── image_request     - 图像请求
│
├── 检测消息 (detection)
│   ├── detection_request  - 检测请求
│   └── detection_result   - 检测结果
│
├── 位姿消息 (pose)
│   ├── pose_transform_request  - 位姿转换请求
│   └── pose_transform_result   - 位姿转换结果
│
├── 指令消息 (command)
│   ├── motion_command    - 运动指令
│   ├── grasp_command     - 抓取指令
│   ├── system_command    - 系统指令
│   └── command_ack       - 指令确认
│
└── 状态消息 (status)
    ├── robot_status      - 机器人状态
    ├── execution_status  - 执行状态
    └── system_status     - 系统状态
```

### 5.3 适配器接口定义

```python
# 适配器抽象接口
class RobotAdapter(ABC):
    """机器人适配器抽象基类"""

    @abstractmethod
    def convert(self, unified_command: UnifiedCommand) -> Any:
        """将统一指令转换为目标格式"""
        pass

    @abstractmethod
    async def execute(self, converted_command: Any) -> ExecutionResult:
        """执行转换后的指令"""
        pass

    @abstractmethod
    async def get_status(self) -> RobotStatus:
        """获取机器人状态"""
        pass

    @abstractmethod
    def validate(self, unified_command: UnifiedCommand) -> ValidationResult:
        """验证指令是否可执行"""
        pass
```

### 5.4 Blender 适配器

```python
class BlenderAdapter(RobotAdapter):
    """Blender 虚拟机器人适配器"""

    def convert(self, unified_command: UnifiedCommand) -> dict:
        """转换为 Blender 指令格式"""
        if unified_command.command_type == "move_joint":
            return {
                "command": "rotate_bones",
                "angles": unified_command.motion_data["joint_angles"],
                "frames": self._speed_to_frames(unified_command.motion_params["speed"]),
                "interpolation": "LINEAR"
            }
        elif unified_command.command_type == "move_cartesian":
            # Blender 需要先进行逆运动学计算
            joint_angles = self._inverse_kinematics(
                unified_command.motion_data["position"],
                unified_command.motion_data["orientation"]
            )
            return {
                "command": "rotate_bones",
                "angles": joint_angles,
                "frames": self._speed_to_frames(unified_command.motion_params["speed"]),
                "interpolation": "LINEAR"
            }
        elif unified_command.command_type == "init":
            return {
                "command": "init_bones",
                "reset_to_home": True
            }
        # ... 其他指令类型

    async def execute(self, blender_command: dict) -> ExecutionResult:
        """通过 WebSocket 发送指令到 Blender"""
        await self.websocket_manager.send_to_client("blender", {
            "type": "blender_command",
            "payload": blender_command
        })
        return ExecutionResult(success=True, command_id=...)
```

### 5.5 AUBO 机器人适配器

```python
class AuboRobotAdapter(RobotAdapter):
    """AUBO 真实机器人适配器"""

    def __init__(self, robot_sdk):
        self.robot = robot_sdk

    def convert(self, unified_command: UnifiedCommand) -> dict:
        """转换为 AUBO SDK 调用参数"""
        if unified_command.command_type == "move_joint":
            return {
                "method": "move_joint",
                "args": {
                    "joint_radian": tuple(unified_command.motion_data["joint_angles"]),
                    "is_block": True
                }
            }
        elif unified_command.command_type == "move_cartesian":
            pos = unified_command.motion_data["position"]
            ori = unified_command.motion_data["orientation"]
            return {
                "method": "move_line",
                "args": {
                    "end_pos": (pos["x"], pos["y"], pos["z"]),
                    "end_rpy": (ori["roll"], ori["pitch"], ori["yaw"]),
                    "is_block": True
                }
            }
        elif unified_command.command_type == "init":
            return {
                "method": "move_joint",
                "args": {
                    "joint_radian": (0, 0, 0, 0, 0, 0),
                    "is_block": True
                }
            }
        # ... 其他指令类型

    async def execute(self, aubo_command: dict) -> ExecutionResult:
        """调用 AUBO SDK 执行指令"""
        method = getattr(self.robot, aubo_command["method"])
        result = method(**aubo_command["args"])
        return ExecutionResult(success=result, command_id=...)
```

## 11. 总结

本设计文档定义了一套统一的通信协议，实现了：

1. **统一消息格式**：所有消息采用一致的 JSON 结构，便于解析和处理
2. **统一指令抽象**：定义了中间层的指令格式，屏蔽了底层差异
3. **适配器模式**：通过适配器将统一指令转换为不同目标的具体格式
4. **模块解耦**：指令解析、转换、执行三层分离，职责清晰
5. **双向通信**：支持图像上传、检测结果返回、指令下发、状态反馈等完整流程

通过这套协议，系统可以方便地扩展支持新的机器人类型，只需实现对应的适配器即可，无需修改核心业务逻辑。
